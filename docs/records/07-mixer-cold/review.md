2. Cold start. Honest modelling, not an exploit, but its size belongs to this window format and should be disclosed. The zero padding was the record's own line in forward(); the verifier feeds 512 bytes and nothing else. train.bin holds 81,779 NULs and 0 NUL NUL pairs, so at position t exactly one order looks like a story start, and every higher order is a context training never produced, landing on rows owned by unrelated contexts. The agent's explanation is half of that. The masks read only position (zeros per order 0, 1, 2, 3, 4, 5, 7, 9, 11) and nothing about where windows are cut. The assumption is true: 0 of 1024 scored dev windows and 1 of 1024 test windows follow a NUL (test also holds window 0, but the file opens mid-sentence), with stories averaging 800 bytes, and cold steps sample random positions of train.bin, the same distribution.

The score does reward this in a way that may not be the intent. Per the agent's paired.py (one seed, dev), positions under 16 carry 0.0061 of the 0.0187, or 33%, and from 16 on carry 0.0126. On the record's params the masked first 16 positions still cost 26.11 bits against 18.23 at the rate of positions 16 to 32, so at most 7.88 bits per window, 0.0154 bpb, remains in this pool for any later entry, and most of that is context nobody has. It carries over only as 2.45 bits per context-free start, in the first 11 bytes: about 0.0005 bpb on a 5,120 byte window, nothing with real preceding context, and once per file in a compressor. Feeding the NUL at a true story start loses nothing, since the masks remove only contexts training never saw. The vote gain runs the other way: 0.00000 under position 16, 0.00164 from 256 to 512. Scoring from position 16 on would remove the question.
